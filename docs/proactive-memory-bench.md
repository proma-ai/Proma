# Proactive Memory 召回评测（bench-recall）

> 日期：2026-08-04
> 脚本：`scripts/bench-recall.ts`
> 运行：`PROMA_DEV=1 bun run scripts/bench-recall.ts`（默认读 `~/.proma/memory`，dev 读 `~/.proma-dev/memory`）

## 一、用途

对当前记忆库跑一组**标准问句集**，客观评估关键词召回的三个核心指标：

| 指标 | 定义 |
|---|---|
| **总体正确率** | 所有问句中判定正确（含正确命中 + 正确沉默）的比例 |
| **召回（Recall）** | 期望命中的问句中，实际正确命中的比例 |
| **误报率（False-Alarm）** | 期望沉默的问句中，误召回的比例（该沉默时沉默是能力） |

## 二、问句集构成

1. **多项目召回（12 问）**：CodeLens / ShopGo / DocFlow 三个模拟项目 + 过期检测 + 技术栈演化 + 近义词难题（"用什么锁"→ 分段锁、"重复支付"→ 幂等），复用压力测试已验证的问句。
2. **误报控制（3 问）**：闲聊/无相关意图（"帮我写一个排序算法"、"今天天气怎么样"、"讲个笑话"），期望 **0 召回**。

判定规则（自动）：
- 期望命中的问句：召回结果中任一 atom 命中 `expectedKeywords` → 正确
- 期望沉默的问句：召回 0 条 → 正确；召回 > 0 条 → False-Alarm

## 三、口径说明（重要）

**本脚本是 Proma 本地问句集，不是第三方评测 harness。**

- 分数**不与** OmniMemEval / LoCoMo / LongMemEval / PersonaMem 等直接可比——那些用统一 harness + 统一 judge 在受控数据集上复现各家记忆服务，本脚本只验证 Proma 自己记忆库的 keyword 召回质量。
- 参考了 OmniMemEval 的"同口径复现"思想（固定问句、固定判定），但数据集与实现完全不同。
- 误报控制参考 ProactiveAgent（ICLR 2025, arXiv 2410.12361）：所有现成模型 Recall 98%+ 但误报 51~65%，"该沉默时沉默"也是能力。

## 四、2026-08-04 实测（dev 库 98 条）

| 指标 | 改进前 | 改进后 | 说明 |
|---|---|---|---|
| 总体正确率 | 80.0%（12/15） | **93.3%（14/15）** | — |
| 召回 | 91.7%（11/12） | **91.7%（11/12）** | 未回退 |
| 误报率 | 66.7%（2/3） | **0.0%（0/3）** | 从 2 个误报降到 0 |

剩余 1 个 miss："你还记得我是谁吗" 走了 recall 意图降级（fallback 返回偏好而非身份）——这是有意的"保 Recall 不沉默"行为，问句集对 fallback 内容期望过严，可接受。

### 本次修复（bench 暴露的真实问题）

1. **纯单字弱命中被归一化放大**（`recall.ts`）：只有单字命中（如"排序算法"的"序"匹配到"程序"）时，归一化把唯一弱命中放大成 1.0 绕过阈值。修复：无任何长度 ≥2 强词命中时，score × 0.1（"帮我写一个排序算法"从误伤天气记忆 → 0 条）。
2. **闲聊意图词误伤项目名**（`recall.ts` 停用词）："今天天气怎么样"命中"天气小程序"项目记忆。修复：将"天气"加入停用词（闲聊意图）；"天气小程序还在维护吗"仍可通过"小程序/程序/维护"召回，项目名实体召回不受影响。

## 五、何时运行

- 修改 `recall.ts` / `query-rewriter.ts` / `embedding.ts` / 停用词后，跑一次确认无回归。
- 记忆库显著变化后（如新项目积累），用于观察召回质量漂移。
- 可加入 CI 或手动回归清单（`scripts/` 下与 smoke-* 并列）。

## 六、后续可选

- 把问句集扩展为 json 文件（`scripts/bench/questions.json`），便于维护与多人共享。
- 增加 hybrid 模式（`PROMA_MEMORY_EMBEDDING=local/api`）与 keyword 模式的对比输出。
- 把期望沉默问句扩充（更多闲聊/无关意图样例），压紧误报率。
