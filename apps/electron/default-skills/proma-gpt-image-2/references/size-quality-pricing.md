# GPT Image 2 定价与降级

价格以 Proma Cloud 服务端 `app/configs/tool_pricing.py` 实际配置为准。

> 1 USD = 7.80 积分
> 实际扣费 = 单价 × `n`
> Edit 模式按**降级后**的实际 size/quality 计费

| size | low | medium | high |
|---|---|---|---|
| **1024×1024** / `auto` | $0.012 / 0.094pt | $0.106 / 0.827pt | $0.422 / 3.29pt |

## Edit 模式自动降级规则（重要）

Edit 模式上游 OpenAI API 只支持 3 种 size：`1024x1024` / `1024x1536` / `1536x1024`。
如果调用方传了其他 size，**服务端自动映射**到最接近的合法值：

| 调用方传入 | 服务端实际发上游 |
|---|---|
| `auto` | `1024x1024` |
| `2048x2048` | `1024x1024` |
| `2048x1152` | `1536x1024` |
| `3840x2160` | `1536x1024` |
| `2160x3840` | `1024x1536` |

同时 **quality 降级**：
- Edit 模式 + `high` → 自动降为 `medium`（上游 high + edit 必定超时）

### Agent 应该如何处理

**调用前不需要做任何降级处理**，按用户意愿传就行：

```javascript
// 用户：「用 GPT 编辑这张图，4K 高质量」
body = {
  prompt: "...",
  image: "...",
  size: "3840x2160",   // 即使是 4K，服务端会降到 1536x1024
  quality: "high"       // 即使是 high，服务端会降到 medium
}
```

**但调用后**，建议在 Markdown 回复里**告知用户实际生成的分辨率**，因为图片可能比用户预期小：

> "已生成图片。注：由于 OpenAI 编辑模式限制，实际分辨率为 1536×1024（请求的 4K 在编辑模式下不支持）。如需 4K 输出，可以先用 Nano Banana 生成 4K 原图，再用本 Skill 做局部编辑。"

## 成本估算示例

- 用户：「用 GPT Image 2 画一张 medium 质量的 1024 海报」
  → text-to-image, n=1, size=1024x1024, quality=medium
  → **0.83 积分**

- 用户：「编辑这张图，4K 高质量」
  → edit, n=1, size=3840x2160 → 实降到 1536x1024, quality=high → 实降到 medium
  → 按 1536x1024 × medium 计费 = **0.64 积分**

- 用户：「生成 4 张 2K 高质量」
  → text-to-image, n=4, size=2048x2048, quality=high
  → 13.17 × 4 = **52.68 积分**（贵！主动告知用户）

**如果总成本超过 5 积分，主动告知用户并询问是否继续**。
